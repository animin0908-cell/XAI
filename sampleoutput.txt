This example uses the IEEE9500 grid model and a dataset generated by simulating single-line outages with OpenDSS.
The examples below are selected from the test set and cover the modeled grids in Franklin County and Adams County.

The model is based on the graph neural network (GNN) from the PowerGraph-XAI project.
Model source:
https://github.com/PowerGraph-Datasets/PowerGraph-XAI
Reused model code: src/gnn/model.py
New regional model code: src/gnn/regional_risk.py

Three major changes were made to the original model:
1. Input adaptation: Node features were expanded from 3 to 4 dimensions to include active power load,
  reactive power load, pre-outage voltage, and markers for the endpoints of the outaged line. Edge features
  were changed to describe branch type, number of phases, and rating to suit the IEEE9500 data.
2. County-level aggregation: Mean and max aggregation within each county were added and combined with
  a whole-grid representation and county-level inputs, extending the original whole-graph prediction
  to separate predictions for each county.
3. Dual-task prediction head: Two outputs were added: problem risk and affected-load fraction.
  The model is trained jointly with classification and regression losses; the regional model is trained
  from scratch, with probability calibration performed separately.


Module Application:
- SHAP: Kernel SHAP is used to calculate how features contribute to county-level risk or affected-load fraction, and to generate descriptions for different audiences.
  https://shap.readthedocs.io/en/latest/generated/shap.KernelExplainer.html
- GNNExplainer: This module is already included in the original XAI framework and can be used to explain important node features and subgraphs.
  https://pytorch-geometric.readthedocs.io/en/latest/generated/torch_geometric.explain.algorithm.GNNExplainer.html

The following describes this project's prediction and explanation process
using IEEE9500 data.

1. Dataset structure
   Data is organized by power grid operating scenarios, with each record
   corresponding to a hypothetical single-line outage.
   Each record includes grid connection points and their connections,
   the load and voltage at each location, and the county to which each
   connection point belongs. Power grid simulations determine whether
   problems occur after the outage and the affected-load fraction,
   providing reference answers for model training and evaluation.

   It should be noted that the current data comes from simulated scenarios,
   rather than real incident records.

   Dataset Sample Input: IEEE9500

  One input-cell excerpt (the value are normalized)
 {
  "load_p": 0.000710367,
  "load_q": 0.001455539,
  "pre_outage_voltage_pu": 1.011691,
  "outage_endpoint_marker": 0,
  "county": "Franklin County",
  "connected_branch": {
    "is_line": 1,
    "is_transformer": 0,
    "number_of_phases": 2,
    "log_rating": 5.056246
   }
 }

2. GNN model input
   The model takes grid connections and operating information as inputs,
   including electricity consumption at each location, pre-outage voltage,
   and parameters such as line and transformer types and carrying capacity.
   The model uses the location of the line assumed to be out of service
   and the county to which each connection point belongs,
   combining this information to make predictions.

3. GNN model output
   The current test model is configured to provide two outputs for each
   county: a problem risk score and an affected-load fraction.
   Affected load includes electricity demand associated with insufficient
   supply, abnormal voltage, or overload-related problems.
   For example, a predicted fraction of 50% means that the model expects
   approximately half of the modeled load to be affected. Currently,
   normal samples are insufficient, so the risk score cannot yet reliably
   reflect the probability of actual problems occurring.

4. SHAP interpretation and organization of model outputs
   SHAP explains how different categories of input information influence
   the current model prediction.
   While keeping grid connections unchanged, reference values are used
   to replace different combinations of input categories, and model
   outputs are repeatedly calculated to determine the direction and
   magnitude of each input's contribution to the prediction.
   The reference values in this project mainly come from the averages
   of the training data.
   After obtaining contribution values, the program generates textual
   explanations according to the needs of different roles:
   Because the dataset is of poor quality and contains missing data,
   parts that cannot be predicted are temporarily displayed as
   "Insufficient data".
